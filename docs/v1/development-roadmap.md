# Cortex v1 delivery roadmap

Effective 2026-10-23. A1–A14 documents remain historical architecture evidence, not the active delivery plan. Their unclosed validation debt is retained. Retire the 82% Goal Meter. Reuse the existing harness; do not replace it with Hermes or another framework.

| Stage | Focus | Dependency | Measured exit gate |
|---|---|---|---|
| 0 | Freeze and audit | Existing repository | Safe local baseline commit and annotated cortex-v1-stage0-baseline tag, evidence ledger, product definition, roadmap and recorded regression/security audit |
| 1 | Reliable brain and cost tracking | Stage 0 gate | Default inexpensive model selected from measured tool-call/schema validity on representative requests; record eligible candidates, denominators, failures, latency, cost, prepaid budget and enforced limits; define and record decision thresholds before trials |
| 2 | First real task | Stage 1 gate | Read-only Gmail + Calendar daily summary succeeds in at least 45 of 50 runs (90%); count complete cases including grounding and permissions, report failures and costs |
| 3 | Voice and fast lane | Stage 2 gate | Daily summary works reliably by real voice; publish repeated end-to-end audio trials, success denominator and latency against thresholds fixed before testing |
| 4 | Always-on Hub | Stage 3 gate | Daily task completes with ASUS asleep; record actual hosting, reconnect/recovery and execution evidence |
| 5 | Basic Android client | Stage 4 gate | Daily task completes from authenticated physical Android; verify identity, results and disconnection behavior |
| 6 | Better hands and eyes | Stage 5 gate | At least 85% complete-case passes on a fresh GUI benchmark plus three regularly passing useful tasks; publish denominators and repeated results |
| 7 | Multi-user and sharing | Stage 6 gate | User accounts, cross-user data isolation and permission boundaries verified with positive and negative tests |
| 8 | Family beta | Stage 7 gate | One relative independently onboards and uses Cortex for one week; record actual usage, failures and support required |
| 9 | Hardening and deferred extras | Stage 8 gate | Security review, conservative recovery, backup/restore demonstration and evidence for each explicitly selected deferred capability |

No stage advances without its evidence. No unrelated features while pursuing a gate. If blocked beyond two days, reduce task scope and document the revised experiment; never relabel partial work as a full pass. Record measurements and remaining uncertainty at every gate. Qualitative gates must receive explicit trial counts and thresholds before implementation/trials; Stage 0 does not invent completed measurements.

Future execution preference: direct APIs/deterministic operations, then Windows UI Automation, then screenshot/pixel fallback. No execution upgrade in Stage 0. Stage 1 may evaluate inexpensive paid inference with prepaid credits and strict budgets; Stage 0 purchases/configures/selects nothing.

## Deferred backlog
Retain A14 code/tests but keep graph orchestration outside v1's critical path until measured workloads justify it. Preserve BLE/Wi-Fi Direct, speaker identification, animated orb/visual polish, generative interactive 2D/3D, additional integrations and deferred A12.2 without expanding them. Hosting, Android, voice and family access follow the stages above. New ideas enter this backlog, not the current stage.

## Stage 1 entry checklist
Stage 0 commit/tag resolvable; ledger and product definition reviewed; regression counts and failures recorded; sensitive/generated artifacts excluded; baseline reproducible from saved manifest; unresolved validation debt explicit. Stage 1 begins only under a subsequent instruction. Before any paid use, obtain funding/provider authorization and define spend caps and evaluation criteria. Stage 1 is NOT_STARTED.
